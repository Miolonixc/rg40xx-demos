# Трансляция на Chromecast для RG40XX H (Knulli)

Экран и звук приставки по Wi-Fi на любой Chromecast или телевизор с Google Cast — так же, как Chrome делает «Трансляцию экрана». Играть можно на телевизоре, держа приставку как геймпад.

## Что входит

| Файл | Куда ставится | Назначение |
| --- | --- | --- |
| `cast-screen` | `/userdata/system/bin/` | Отправитель Cast Streaming и команды управления |
| `app/cast_app.py`, `app/Chromecast.sh` | `/userdata/roms/tools/` | Приложение Chromecast |

Ничего доустанавливать на Knulli не нужно: протокол Cast написан на стандартном Python, шифрование — через libcrypto из OpenSSL, звук — через libopus, видео кодирует системный ffmpeg (libx264).

Настройки (Chromecast по умолчанию, экран и звук приставки, картинка, качество, задержка, частота кадров) хранятся в `/userdata/system/cast-screen.conf`, состояние идущей трансляции — в `/tmp/cast-screen.state`, лог — в `/tmp/cast-screen.log`.

## Установка с Mac

```sh
tools/cast-screen/install.sh 192.168.2.173
```

Вторым параметром можно сразу задать Chromecast по умолчанию (имя как в `cast-screen list`). Установщик останавливает идущую трансляцию, добавляет Chromecast в «Инструменты» и убирает старые пункты «Cast start» / «Cast stop». Если EmulationStation поставлена на паузу запущенной игрой (так делает, например, запуск GTA), список игр не трогается — после игры установщик нужно запустить ещё раз.

## Приложение

Ищет в сети устройства Cast с экраном (колонки и группы колонок пропускает). Крестовина выбирает, A на устройстве начинает трансляцию на него и запоминает его как последнее, X ищет заново. Трансляция продолжается после выхода из приложения — можно запускать игру. Выход — B, Start, Menu или пункт Exit. Интерфейс на английском, **Language / Язык** переключает на русский (`/userdata/system/configs/cast-app.conf`).

- **Остановить трансляцию** — первая строка, красная, пока трансляция идёт. Ещё остановить можно, нажав A на телевизоре, куда идёт трансляция (он помечен «● ИДЁТ · A — стоп»).
- **Экран на приставке** / **Звук на приставке** — «ВКЛ, тут и на ТВ» или «ВЫКЛ, только на ТВ» на время трансляции: с обоими выключенными приставка остаётся просто геймпадом. Применяются сразу. Экран гаснет через подсветку (0), звук — глушением выхода PipeWire, на телевизоре всё остаётся. Процессор это не разгружает: игра всё равно рисует кадр, который передаётся на ТВ.
- **Картинка на ТВ** — «4:3 как есть» (чёрные полосы по бокам), «Растянуть на 16:9» (пиксели помечаются как широкие в потоке H.264, телевизор растягивает сам, без нагрузки на приставку), «Приблизить до 16:9» (вырезается середина 640×360, верх и низ экрана теряются, пропорции сохраняются).
- **Качество** — 2, 3 или 5 Мбит/с. Больше — чётче в динамичных сценах, но нужен хороший Wi-Fi.
- **Задержка** — буфер Chromecast 150, 250 или 400 мс. Меньше — отзывчивее, больше — меньше рывков на слабом Wi-Fi.
- **Частота кадров** — 30, 25 или 20 к/с. Меньше кадров — меньше нагрузка на процессор в тяжёлых играх.

Картинка, качество, задержка и частота кадров меняют сам поток, поэтому идущая трансляция перезапускается (около 3 секунд).

## Утилита

```sh
cast-screen list                      # Chromecast в сети
cast-screen start ["FarFromMe TV"]     # трансляция в этом терминале (по умолчанию — устройство из настроек)
cast-screen background ["FarFromMe TV"]  # то же в фоне, лог в /tmp/cast-screen.log
cast-screen stop
cast-screen status
cast-screen set device "FarFromMe TV"
cast-screen set screen on|off         # экран приставки во время трансляции
cast-screen set sound on|off          # динамик приставки во время трансляции
cast-screen set aspect 4:3|stretch|zoom
cast-screen set bitrate 2000|3000|5000
cast-screen set delay 150|250|400
cast-screen set fps 30|25|20
```

Параметры `start` перекрывают настройки на один запуск: `--aspect`, `--delay MS`, `--bitrate KBPS`, `--fps N`; ещё `--no-audio` и `-v` (все сообщения протокола).

## Как это работает

- **Управление:** TLS на порт 8009, сообщения CastMessage. Запускается встроенный приёмник «Chrome Mirroring» (`0F5096E8`), потоки согласуются сообщениями OFFER/ANSWER.
- **Видео:** скрипт 30 раз в секунду читает показываемую страницу `/dev/fb0` через `pread()` и отдаёт ffmpeg, тот кодирует H.264 (ultrafast, zerolatency). Встроенный захват ffmpeg (`-f fbdev`) копирует из некэшируемого mmap и тратит в 4 раза больше процессора.
- **Звук:** `parecord` пишет монитор основного выхода PipeWire, libopus кодирует кадры по 20 мс. Глушение выхода (звук приставки ВЫКЛ) монитор не затрагивает; выключение `LINEOUT` в amixer рвёт поток, поэтому не используется.
- **Передача:** каждый кадр шифруется AES-128-CTR и режется на пакеты Cast RTP. RTCP-отчёты отправителя синхронизируют часы и губы, потерянные пакеты по запросу приёмника отправляются ещё раз. Отправка не блокируется: если Wi-Fi не успевает, пакет выбрасывается и запрашивается заново.
- **Wi-Fi:** на время трансляции выключается энергосбережение адаптера — с ним пинг до Chromecast прыгал до 200 мс и поток вставал.
- Если приёмник 20 секунд не подтверждает кадры, трансляция останавливается и возвращает экран и звук приставки.

Нагрузка при 640×480, 30 кадрах/с: ffmpeg около одного ядра, скрипт около половины ядра.
